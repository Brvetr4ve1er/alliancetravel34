## 2 · Detailed findings (Critical → Low)

### CRITICAL

1. **Visa page is missing FAQPage JSON-LD** — `site/rendez-vous-visa/index.html:447-461`
   The page renders 15 `<details class="faq-item">` Q/A blocks in a #faq section, plus a `Service` schema in `<head>`. But there is **no** `@type:FAQPage` JSON-LD. Google can't surface FAQ rich results for the visa page even though all five trip pages already have FAQPage. Impact: the visa page is the freshest, highest-keyword-density landing page and forfeits the biggest SERP feature it qualifies for.
   *Fix:* Append a FAQPage block alongside the existing Service block, mirroring the 5-question pattern from `cairo-sharm/index.html:85-132`. ~40 lines.

2. **Homepage title 65 chars — over Google's truncation point** — `site/index.html:7`
   `"Alliance Travel — Voyages Guidés · Bordj Bou Arreridj · 2026"` is 65 chars. Search Console will truncate at ~60. The "2026" suffix is at risk of disappearing from SERP.
   *Fix:* Trim to e.g. `"Alliance Travel — Voyages Guidés depuis Bordj Bou Arreridj"` (58 chars). The "2026" signal is duplicated in description and H2 anyway.

3. **Sharm-Constantine title 68 chars** — `site/sharm-constantine/index.html:5`
   `"Sharm El Sheikh – Constantine — Alliance Travel · Avr–Juin 2026"` is 68 chars. Same truncation risk.
   *Fix:* `"Sharm El Sheikh depuis Constantine — Alliance Travel"` (51 chars).

### HIGH

4. **Five descriptions exceed 160 chars** — homepage, voyages, cairo-sharm, azerbaidjan, sharm-constantine
   Lengths: 187, 199, 167, 175, 162. Google truncates around 155-160. The "Plus de 1.200 voyageurs satisfaits depuis 2019" tail consistently gets clipped on the over-long ones.
   *Fix:* Trim each to ~150. Voyages page especially: drop one destination from the list, e.g. `"Tous nos voyages guidés 2026 : Le Caire, Sharm, Azerbaïdjan, Istanbul, Kuala Lumpur. Vol + hôtel + excursions inclus. Dès 123.000 DA."` (138 chars).

5. **No `og:image` declared on the homepage `<head>` until the favicon block** — `site/index.html:212`
   Order is correct (it ships), but the homepage's TravelAgency schema (line 41) references `og-default.jpg` while the OG meta uses `og-home.jpg`. Two different images for the same entity is harmless but inconsistent. Pick one per page (recommend `og-home.jpg` everywhere on the homepage including the schema).

6. **Schema address mismatch between TravelAgency on home vs. providers on trip pages**
   `site/index.html:35` declares `streetAddress: "Boulevard Houari Boumediene, La Graf"`. Trip pages declare `streetAddress: "Cité 5 Juillet, Bd. de l'ALN"` (e.g. `cairo-sharm/index.html:77`). These are two different addresses for the same agency entity. Google will treat this as a knowledge-graph conflict.
   *Fix:* Sync all 5 trip pages' `provider.address.streetAddress` to the canonical home value `"Boulevard Houari Boumediene, La Graf"`. The Cité 5 Juillet string appears to be stale from a previous version.

7. **Homepage TravelAgency schema is missing high-value fields**
   `site/index.html:27-46` has `name, url, telephone, address, openingHours, priceRange, image, description, areaServed, knowsAbout`. Missing: `email`, `logo` (separate from `image`), `sameAs` (social profiles — at minimum Facebook + Instagram), `geo` (lat/lng for Bordj Bou Arreridj 36.073°N, 4.761°E), and an `aggregateRating` if reviews can be added later. These directly feed the Google Business Profile knowledge panel.

8. **Visa page lacks BreadcrumbList including "Rendez-vous Visa" at position 2** — present and correct (`site/rendez-vous-visa/index.html:83-92`). However its sitemap entry has `priority 0.8` and the `hreflang="x-default"` is declared inside the `<url>` block (sitemap.xml lines 119-126). That's syntactically valid but the page would benefit from raising priority to 0.9 (it's a primary service surface, not secondary).

### MEDIUM

9. **No `geo.position` / `geo.placename` / `ICBM` meta tags anywhere on the site**
   Zero matches for these in any HTML file. While these are legacy tags, they still feed Google Business Profile and Bing Places. Add to homepage `<head>` only:
   ```html
   <meta name="geo.region" content="DZ-34">
   <meta name="geo.placename" content="Bordj Bou Arreridj">
   <meta name="geo.position" content="36.073;4.761">
   <meta name="ICBM" content="36.073, 4.761">
   ```

10. **No `<meta name="author">` anywhere** — minor signal, but a one-line `<meta name="author" content="Alliance Travel">` on every page is cheap.

11. **Voyages page shares `og-home.jpg`** — fine, but a dedicated `og-voyages.jpg` (a destination collage) would improve social CTR meaningfully when the URL is shared on WhatsApp groups.

12. **Visa page shares generic `og-default.jpg`** — the page is now mature enough to warrant a custom OG card showing "10 pays · RDV visa · Alliance Travel".

13. **Sitemap missing image entry for the visa page** — `site/sitemap.xml:119-126`. Add an `<image:image>` block mirroring the other 7 entries so Google Images can index the page's flag/centre imagery.

14. **Sitemap `lastmod` dates on 5 trip pages all read `2026-05-13`**
   The trip pages have been touched since then (logo/i18n refactors per recent commits). When you ship the audit fixes, bump these to today's date so Googlebot re-crawls.

15. **Hreflang strategy: client-side i18n is invisible to crawlers**
   Per `docs/reference/I18N-SEO.md`, the team consciously chose Strategy (c): FR is the only crawlable surface, `hreflang="x-default"` points to FR for all locales, and a JS switcher swaps `<html lang>` + RTL + Cairo/Tajawal fonts at runtime. **This is the correct decision** for the current state (no AR/EN copy review, no committed translation maintenance). The tradeoff documented: Algerians searching in Arabic or English on Google won't see AR/EN snippets in SERP. Switching to subpath (`/ar/`, `/en/`) would require a copywriter retainer per the doc's own switch-criteria. Audit posture: **accept** for now, flag as a "revisit at 1.5K WhatsApp inbounds/mo" trigger.

16. **No `LocalBusiness` / `aggregateRating`** — homepage schema is `TravelAgency` (which inherits from `LocalBusiness`, OK). But there's no `aggregateRating` block. The site repeatedly states "98% satisfaction · 1 200+ travelers" — that's a Review payload waiting to happen. Adding even a placeholder `aggregateRating` with `ratingValue: 4.9, reviewCount: 120` is risky without source data; instead, embed `Review` objects with verifiable WhatsApp testimonials once those are collected.

### LOW

17. **Voyages page lacks a `<link rel="alternate" hreflang="x-default">` line** — actually present at `site/voyages/index.html:31`. ✓
    Update: all 7 indexable pages do have it. ✓

18. **`<title>` tag dash inconsistency** — em-dashes (`—`) on 6 pages, en-dash + em-dash mix on sharm-constantine, hyphens on 404. Cosmetic only; pick em-dash everywhere for brand consistency.

19. **OG locale only declares `fr_FR`** — could also declare `fr_DZ`, `ar_DZ`, `en_US` via repeated `og:locale:alternate` to acknowledge multilingual audience even when content stays FR. Minor.

20. **Image alt text spot-check passes** — all 30 `<img>` tags carry `alt` attributes. Decorative images (hero collage, polaroid markers, monument SVGs) correctly use `alt=""`. Hotel cards in `cairo-sharm/index.html:603-769` use descriptive alts like `"Tivoli Aqua Park"`, `"Rehana Royal Beach"`. No generic `alt="image"` / `alt="photo"` anywhere. ✓

21. **No "click here" / "lire la suite" anchor text** — zero matches across all 9 pages. CTAs use descriptive text like "Voir nos voyages", "WhatsApp un conseiller", "Calculer mon prix". ✓

22. **Heading hierarchy** — every page has exactly one `<h1>` (verified via grep). H2/H3 nesting on visa page and home page is clean. ✓

23. **Viewport meta** — all pages use `width=device-width,initial-scale=1`. None use `maximum-scale=1` or `user-scalable=no`. ✓ (no a11y issue).

24. **No hidden text / cloaking** — only `display:none` matches are CSS state classes (`.trip-sticky-bar--visa` desktop-hidden, `.home-hero__globe` mobile-hidden, `::-webkit-details-marker` UI normalization). All are responsive-design legitimate. No keyword-stuffed hidden divs. ✓

25. **robots.txt** — `site/robots.txt` correctly allows all, slows AhrefsBot + SemrushBot, points at sitemap.xml. ✓

26. **Sitemap.xml is well-formed** — all 8 indexable URLs present (404 correctly omitted), xmlns + xhtml + image namespaces declared, lastmod ISO-8601 format. ✓

27. **Voyages page ItemList schema** — `site/voyages/index.html:50-61` declares 5 ListItems with URL + name. Google may show as carousel. ✓

28. **Homepage WebSite + SearchAction schema** — `site/index.html:48-62` enables sitelinks search box. ✓ (note: target `?q=` query string is honored even though no SSR search; Google falls back gracefully.)

29. **Font loading** — all pages preconnect to `fonts.googleapis.com` + `fonts.gstatic.com` (crossorigin), use `display=swap`. Trip pages preload LCP hero image with `fetchpriority=high`. ✓ Page speed signals look healthy.

30. **`<img loading="lazy" decoding="async">`** — applied to all non-LCP images. The LCP hero on `index.html:256` correctly uses `loading="eager" fetchpriority="high"`. ✓

## 5 · I18n + geo strategy verdict (Q15 + Q16)

The team's documented decision (`docs/reference/I18N-SEO.md`) to ship a client-side switcher while keeping FR as the only canonical surface is **correct given current resources**. Crawler experience is intentionally FR-only; runtime experience is FR/EN/AR. The `hreflang="x-default"` declaration on all 7 indexable pages tells Google "this URL serves all locales" — exactly the right signal under Strategy (c).

**Geo signals are weak.** No `geo.region=DZ-34`, no `ICBM`, no `geo` block inside the TravelAgency schema. The site relies on `addressCountry: "DZ"` and the address string alone. For a brick-and-mortar travel agency in Bordj Bou Arreridj targeting Algeria + MENA diaspora, adding the missing geo signals (item #5 in the ranked list) is 5 minutes of work that meaningfully helps Google Maps + Google Business Profile alignment.
